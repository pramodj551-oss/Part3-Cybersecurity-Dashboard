# 🛡️ AI-Powered Cybersecurity Dashboard

**Part 3 of the End-to-End Applied AI & ML Data Product Capstone Project**

An interactive Streamlit dashboard for cybersecurity incident exploration, EDA, model explainability, regression metrics, and severity-score prediction using the production artifacts generated by Part 2.

## Architecture

Part 1 provides descriptive analytics. Part 2 provides the leakage-aware **severity-score regression** pipeline. Part 3 is the presentation/inference layer and must consume the Part 2 artifacts rather than retrain or refit preprocessing in the dashboard.

```text
Part 2 raw dataset
      ↓
Part 2 fitted preprocessor + best regression model + feature contract
      ↓
Part 3 Streamlit dashboard
      ↓
EDA | Explainability | Metrics | Prediction
```

## Dataset Contract

The committed source dataset is:

```text
data/raw/cybersecurity_incident_reports.csv
```

Required prediction inputs are:

- `records_affected`
- `detection_time_hours`
- `ransom_demand_usd`
- `sector`
- `region`
- `attack_type`
- `threat_actor`
- `data_exfiltration`
- `zero_day_used`

Target: `severity_score`.

The following post-incident fields are **excluded from prediction**: `downtime_hours`, `response_team_size`, `regulatory_fine_usd`, and `resolved_within_7_days`. This matches the Part 2 prediction-time contract and prevents response/outcome leakage.

## Runtime Artifact Contract

Prediction requires these Part 2 artifacts:

```text
models/best_model.pkl
models/preprocessor.pkl
models/feature_columns.pkl
```

Evaluation/explainability pages additionally consume:

```text
outputs/evaluation_report.json
outputs/metrics.json
outputs/feature_importance.csv
```

These generated runtime artifacts are intentionally external to this repository. The dashboard **does not create fake placeholders** when they are missing. `src/model_loader.py` fails closed with a clear error, while CI reports external artifact availability separately.

Generate/sync the artifacts from the Part 2 pipeline before enabling production prediction.

## Installation

```bash
git clone https://github.com/pramodj551-oss/Part3-Cybersecurity-Dashboard.git
cd Part3-Cybersecurity-Dashboard
python -m venv venv
# Windows: venv\\Scripts\\activate
# Linux/macOS: source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

Run:

```bash
streamlit run app.py
```

The `pages/` directory is the authoritative Streamlit multipage UI. `app.py` is intentionally only the application entry point and landing page; it does not duplicate the page navigation with placeholder implementations.

## Dashboard Modules

- **Home** — project overview and runtime requirements.
- **Dataset Explorer** — CSV upload, schema/quality summary, preview, missing-value analysis, and download.
- **EDA Dashboard** — interactive target distribution, correlations, descriptive statistics, and dataset information.
- **Prediction** — CSV upload and inference using the fitted Part 2 artifacts.
- **Feature Importance** — deterministic STEP 20 feature-importance artifact visualization.
- **Model Performance** — regression MAE, RMSE, and R² metrics.

## CI Validation

GitHub Actions is the authoritative source for execution evidence. README claims alone do not establish production readiness.

CI validates:

1. Python compilation for application and tests.
2. Application-module importability.
3. The committed raw-dataset path and required schema.
4. Runtime artifact availability when artifacts are present, otherwise an explicit `SKIP` because generated artifacts are external.
5. Unit tests, including the fail-closed runtime loader contract and STEP 20 explainability tests.

## STEP 20 — Explainability

`src/explainability.py` provides deterministic model-native feature importance with a linear-coefficient fallback and writes the normalized `feature,importance` CSV contract used by the dashboard.

## Production Readiness Status

**Source-code readiness:** CI-tested dashboard architecture.

**Prediction readiness:** requires the three Part 2 runtime artifacts to be synced into `models/`.

Therefore the repository must **not** be described as fully deployment-ready until artifact synchronization and an actual prediction smoke test have passed in the target deployment environment.
